JarPilot: deploying JARs to IBM i without the drama

Every install validated, checksummed, backed up and logged, with rollback one command away.

By Gaurav Gupta · 10 October 2026 · 4 min read · Latest v1.2.1

Copying a JAR into the IFS sounds simple until a half-written file, a wrong owner or a missing backup takes a server down. JarPilot, started on 10 October 2026, turns that copy into a repeatable, safe procedure.

How each install works

Validate the JAR → SHA-256 check → back up the current JAR → atomic replace → CHGAUT/CHGOWN → optional restart CL → log and history. If something is wrong, a single rollback restores the previous version, and -DryRun previews every step first.

Use it from anywhere

  • From Windows: jarpilot.ps1 uploads and installs over SSH in one command.
  • On IBM i: jarpilot.sh runs in PASE/QSH.
  • From 5250 or the job scheduler: a CL wrapper, CALL JARPILOT.
  • From the editor: a VS Code extension. Right-click a .jar and choose Install.
  • Server setup: upload a setup JAR and JarPilot answers the installer's questions, checking each answer on the IBM i first so a second server never reuses an existing directory or library.

Skills applied

IBM i IFS & PASE (QSH), CL (CRTBNDCL, CHGAUT, CHGOWN), SSH, PowerShell, Bash, SHA-256 integrity, atomic deployment & rollback, VS Code extension
