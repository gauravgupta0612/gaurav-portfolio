DevSuite: one engine, five focused extensions

Why I split one large idea into small tools that share a single code-analysis core.

By Gaurav Gupta · 9 October 2026 · 5 min read · Latest v0.1

Large extensions that try to do everything end up doing nothing well. DevSuite, started on 9 October 2026, takes the opposite approach: one shared analysis engine (@devsuite/core, with no VS Code dependency) and several small extensions, each focused on one job and each released on its own.

The five extensions

  • RepoPilot: architecture, entry points, build commands, modules, a dependency map and an onboarding guide.
  • DevImpact: what a change affects, an impact score, and which tests to run.
  • CodeGuard: a prioritised risk report for changes (secrets, security, regressions, tests, config and IBM i), also available as a CLI and a pre-commit hook.
  • TraceLens: every API endpoint, traced through to database and external calls.
  • BugTrail: a searchable history of errors, attempts and fixes that warns you when a fixed bug comes back.

The engine indexes JavaScript/TypeScript, Python, Java/Kotlin, Go, C# and IBM i RPG, CL, DDS, SQL and COBOL. The DevSuite Pack installs all five at once. Each extension has its own GitHub Actions release workflow.

Skills applied

Monorepo design, shared analysis engine, parsers for JS/TS, Python, Java, Go, C# and IBM i RPG/CL/DDS/SQL/COBOL, dependency graphs, GitHub Actions release pipelines
