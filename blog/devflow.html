DevFlow: a productivity toolkit that works offline

Checking environments, guarding commits and diagnosing failed builds, with no AI subscription required.

By Gaurav Gupta · 19 October 2026 · 5 min read · Latest v0.1.0

Many lost hours are not spent on hard problems. They go to a missing node_modules, a JDK that is one version too old, a secret pushed by accident, or a Jenkins log nobody wants to read. DevFlow, first built on 19 October 2026, deals with those small problems in one place, and it works offline.

Five tools in one

  • Environment Doctor. Detects the project's stacks (Node, Java Maven/Gradle, Python, Go, .NET, Rust, Docker, Make), checks the required tools and versions, compares .env with .env.example, and offers one-click fixes.
  • Git Assistant. Summarises changes, scans added lines for secrets with 15 rules, writes a Conventional Commit message, and runs pre-commit and pre-push checks.
  • Build Doctor. More than 45 rules for Maven, Gradle, javac, SSL certificates, npm, Node, TypeScript, Jest and Python, applied to a selection, a log file, the clipboard or a build it runs for you.
  • API Workspace. .http and .rest files with Send Request and Compare Environments.
  • Project Dashboard. The state of the project on a single page.

DevFlow 0.1.0 is packaged as a .vsix. It is not on GitHub yet; contact me if you would like to try it.
